<h2>一、交付参数：从下单到可用的四个时间点</h2>

<p>把「开通」拆成四个时间点，比承诺一个笼统的时长有用得多。四个点分别是：付款完成、凭据下发、环境可连、账号首登成功。任何一个点卡住，都知道该找谁。</p>

<h3>时间点一：付款到凭据下发</h3>
<p>现货资源通常在几分钟到两小时内下发凭据，含账号密码或白名单授权。这一段的瓶颈在库存与审核，不在技术。如果超过四小时没收到，直接问库存状态，不要反复催「好了吗」。</p>

<h3>时间点二：凭据到可连</h3>
<p>凭据到手之后，本地配置一般需要五到十五分钟：导入代理、验证认证方式、确认端口可达。这一段如果反复失败，先排查本地网络与防火墙，再排查凭据是否复制错误。端口填错是最常见的原因。</p>

<h3>时间点三：可连到环境就绪</h3>
<p>如果方案包含一号一环境，还要多一步：浏览器实例、用户目录、时区语言、指纹配置。手工配三到五个实例大约需要半小时到一小时；通过模板或快照批量部署，可以压到十分钟内。</p>

<p><strong>时间点四：环境就绪到首登成功。</strong>首登是整个交付的验收点。登录能完成、页面加载完整、没有额外验证，才算交付完成。首登失败时要记录报错原文与当时出口地址，这两个信息决定了后续排查方向。</p>

<h2>二、网络参数：协议、端口、会话粘性</h2>

<p>网络参数决定「连得上」和「连得稳」。这三个词看着技术，实际影响的是日常使用的顺手程度：协议影响兼容性，端口影响可达性，会话粘性影响长时间在线会不会被中途换出口。</p>

<h3>协议：HTTP 与 SOCKS5 怎么选</h3>
<p>HTTP 代理兼容性最好，浏览器和大多数工具都支持，适合网页端操作。SOCKS5 更底层，支持更多协议类型，适合同时要走网页和接口的场景。如果只做浏览器操作，HTTP 就够；如果有脚本直连接口，优先 SOCKS5。</p>

<h3>端口：白名单与固定端口</h3>
<p>有些方案要求先把使用方的公网地址加入白名单才能连，好处是不用传账号密码，坏处是换网络就要改白名单。固定端口的方案更省事，但要确认端口在续费周期内不变。端口变更会让已配置好的环境全部失效，属于要提前问清楚的一项。</p>

<h3>会话粘性：粘多久、怎么续</h3>
<p>住宅代理有「每次请求换出口」和「一段时间内固定出口」两种模式。前者适合采集，后者适合登录与长期在线。做账号运营必须选粘性会话，粘性时长常见从十分钟到数小时不等，长的可以到一整天。粘性到期后会换出口，如果正好在操作中途到期，就会出现「用着用着忽然要验证」。所以粘性时长要覆盖你的典型连续操作时长。</p>

<h2>三、账号参数：一号一环境落到哪几项</h2>

<p>一号一环境不是一句口号，它对应一组具体参数。少配一项，隔离就打了个折扣。</p>

<h3>参数一：出口地址与账号的绑定关系</h3>
<p>一个账号对应一个出口地址，且这个对应关系要能查、能导出。绑定关系存在脑子里是最危险的做法，人一走就断。建议用表格维护，字段包括账号编号、出口地址、城市、运营商、绑定时间。</p>

<h3>参数二：环境实例的独立性</h3>
<p>每个账号一个独立的浏览器实例与用户目录。共用用户目录意味着 Cookie、缓存、本地存储全部混在一起，出口再独立也没用。这一项在批量部署时最容易被图省事跳过。</p>

<h3>参数三：时区、语言与出口城市的一致性</h3>
<p>三项要落在同一个地区。时区设错是最常见的低级错误，一个出口在洛杉矶但时区设成东八区的环境，本身就是一个明显的矛盾信号。部署模板里把这三项写死，比每次手工设置可靠。</p>

<p><strong>参数四：并发上限。</strong>每个出口同时承载多少连接，通常有上限。超过上限后表现为请求排队或直接失败。常见单出口并发在几十个连接量级，具体看方案。批量跑任务前先测一遍上限，再决定任务分片数量。</p>

<h2>四、售后参数：报修、换线、复盘的时限口径</h2>

<p>售后是参数表里最软的一项，但最能拉开差距。自营方直接接入处理、不走转卖，意味着报修之后不需要经过中间层转述，响应链条短一截。</p>

<h3>报修入口与响应时限</h3>
<p>问清三件事：报修走工单还是即时消息；工作时段是几点到几点；首次响应承诺多久。工作时段内一到四小时是常见口径，夜间通常顺延。这些数字写进协议附件，比口头承诺可执行。</p>

<h3>换线时限与替代方案</h3>
<p>换线不只是「给个新地址」，还要保证新地址的城市与运营商与原来一致，否则账号的登录地就跳了。所以换线时限要包含「同城同年运营商替代」这一条，否则换来的可能是另一堆新问题。</p>

<h3>复盘与记录</h3>
<p>每次故障处理完，要求给一份简短复盘：什么时间、什么现象、定位到哪一层、怎么处理。攒够三五份，你就知道自己这套线路的薄弱点在哪，扩量时能提前规避。</p>

<h2>五、参数表怎么用</h2>

<p>把上面四组参数做成一张表，采购时逐项填「确认值」，使用一个月后填「实测值」。两者对不上的项，就是下次谈判的重点。多数人只填确认值，用起来才发现出入，那时候议价空间已经没了。</p>

<p>参数表还有一个用处：换人接手。新同事拿到这张表，不用问任何人就知道每个账号配的哪条出口、协议端口是什么、粘性多长、出问题找谁。这比任何交接文档都直接。</p>

<h2>常见问答</h2>

<h3>开通当天就能用上吗？</h3>
<p>答：现货资源多数可以，从付款到首登成功通常在两小时内完成。含人工部署环境的方案，视实例数量与是否有模板，可能需要半天。下单前把「给凭据」和「环境就绪」分开确认。</p>

<h3>粘性会话要设多长？</h3>
<p>答：覆盖你的典型连续操作时长即可。日常登录与对话场景，设数小时比较稳妥；批量采集可以短一些，甚至每次请求换出口。粘性到期换出口正好落在操作中途，是最容易触发验证的时机。</p>

<h3>HTTP 和 SOCKS5 需要都开吗？</h3>
<p>答：按用途选一个就够。只有浏览器操作选 HTTP，脚本直连接口选 SOCKS5。两个都开反而增加配置复杂度，也更容易在排查时分不清是哪一层的问题。</p>

<h3>怎么确认售后是自营而不是转卖？</h3>
<p>答：看三处。报修后是否由同一方直接处理、换线时能否给出同城同年运营商的具体替代、故障复盘是否带时间线与层级判断。转卖的方案在这三处通常只能给模糊答复。</p>
